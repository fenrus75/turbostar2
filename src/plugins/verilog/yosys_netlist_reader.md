# yosys_netlist_reader

## Goals & Constraints
- Parses elaborated Yosys JSON netlists generated via `yosys ... prep -flatten; write_json netlist.json`.
- Extracts hierarchy netnames, bit IDs, source locations (`src`), and cell connections.
- Bridges the simulation trace domain (full signal names in VCD traces) to the hardware source code domain (`file.sv:line`).
- Token efficiency: emits compact, concise summaries for LLMs without bloated AST dumps or redundant clickable markdown anchors.
- Robust source line parsing: strips column numbers and converts multi-span ranges (e.g. `file.sv:24.9-31.12`) into concise line numbers (`file.sv:24-31` or `file.sv:24`).

## Lessons Learned
- When Yosys runs `prep -flatten`, it flattens module instances into the top module while preserving hierarchical net names (`cpu8008.A_reg.value`) and exact source line coordinates (`src`).
- Every wire connected across module boundaries shares identical bit IDs in its `bits` array, allowing instant lookup of all interconnected ports across the hierarchy without manually walking port maps.
- **RTL Source Prioritization over Techmap Templates**: In post-synthesis netlists, Yosys frequently annotates cells and nets with piped source locations (e.g. `/usr/share/yosys/ice40/cells_map.v:26.33-27.52|sv/alu/alu.sv:45.10-45.25`). When cleaning source locations, `yosys_netlist_reader` checks for and filters out internal techmap/cell library files (`cells_map.v`, `cells_sim.v`, `arith_map.v`, `brams_map.v`, `share/yosys`, `techmap.v`), ensuring the user's actionable RTL location is selected instead of vendor fabric templates.
- **Techmap LUT Vector Suffix Suppression & Register Inference**: When Yosys techmaps `$lut` primitives via `cells_map.v`, it emits synthetic multi-bit LUT input vectors named `<signal>_SB_LUT4_...` where `[0..3]` index the 4 LUT inputs rather than bits of `<signal>`. `normalize_net_name` strips everything from the earliest `_SB_`, `$SB_`, or `$func$` marker onward without re-attaching trailing `[i]` indices that belong to the LUT input vector, while preserving true multi-bit indices before `$SB_IO` (e.g. `LED[1]$SB_IO_OUT -> LED[1]`). Additionally, `infer_register_from_src` inspects the `always_ff` source block of sequential DFF cells (`<=` LHS assignments and `next_<reg>_SB_DFF*_D` patterns) to recover true register names (such as `flags` or `value_reg`) when ABC9 rewires `Q` output nets to downstream LUT wires.
- **Shared `always_ff` & Submodule Instance Disambiguation via Yosys Wire Connectivity (`build_correlation_tables`)**: When an RTL coordinate range defines multiple registers (e.g., `flags`, `input1_reg`, `input2_reg` in a shared `always_ff` block) or a parameterized submodule (`register.sv`) is instantiated multiple times, `build_correlation_tables` resolves the exact hierarchical instance scope from `Q`/`E`/`D` pin user nets and disambiguates multi-register `always_ff` cells using: (1) direct `D`-pin RHS net matching (`input1_reg <= input1`), (2) 1-hop upstream `D`-driver LUT input net matching (`ip_plus_one <= next_ip + 1`), and (3) wire-connectivity elimination of candidate LHS registers whose known `Q` or simple `D` nets do not contain the DFF's bit IDs.
- **Project-Relative `file:line` Display & Smart RTL Code Snippet Extraction (`clean_display_location` & `extract_source_snippet`)**: `clean_display_location` converts absolute file paths emitted by on-demand synthesis into concise project-relative paths via `fs_utils::make_relative_to_project`. `extract_source_snippet` extracts either a 1-line inline statement snippet (`max_lines == 1`, capped at 80 chars, scoring candidate lines in multi-line `always_ff` spans by non-reset LHS assignment match against the resolved signal hint) or a multi-line numbered snippet (`max_lines > 1`).
