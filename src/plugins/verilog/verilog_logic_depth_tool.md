# verilog_logic_depth_tool

## Goals & Constraints
- Analyzes the structural layers of logic (LUT/gate depth) and standalone synthesized area (LUTs, Flip-Flops, Carry, RAM/DSP) of a Verilog/SystemVerilog module to evaluate timing and resource feasibility pre-place-and-route.
- Reports `In -> Reg`, `Reg -> Out`, `Reg -> Reg`, and `In -> Out` logic depths, the top worst critical paths mapped to source RTL coordinates, and an `Area Summary` at the end of the report.
- Purely read-only and side-effect free, leaving sidecar file creation to the dedicated `verilog_update_timing` tool and `turbostar-verilog-update-timing` CLI.

## Lessons Learned
- Sidecar file generation is handled by the dedicated `verilog_update_timing` tool, keeping `verilog_logic_depth` purely read-only and safe for read-only subagents.
- Providing both a table summary and a step-by-step hop breakdown allows the LLM to understand both the high-level interface contract and the exact line of SystemVerilog causing a long combinational chain.
- If `safe_file` is supplied without an explicit module name, the tool derives the target from the file or auto-detects the top module in the synthesized AST. If `module` is omitted entirely, defaults to `top_module` from `turbostar.json`, scanning synthesizable files under `sv_path`.
- **Bottleneck Grouping by Sink**: In wide datapath registers (e.g. 16-bit PC counters, 32-bit ALU operands), separate source bits all converge on the same endpoint register through identical logic chains. Reporting separate paths per source bit crowded out genuinely distinct bottlenecks. Defaulting `group_by_sink: true` collapses these converging paths into a single bottleneck entry listing all converging source signals and bit ranges (`[0..15]`), while allowing callers to request raw paths via `group_by_sink: false`.
- **Consecutive Unlabeled Logic Collapse & De-Mangling**: Combinational paths often pass through intermediate anonymous gate networks between labeled RTL statements. When `collapse: true` (default), maximal consecutive runs of unlabeled `[logic]` hops are merged into a single `[logic] (N LUTs)` stage without crossing across labeled RTL lines, preserving meaningful RTL anchors while eliminating row verbosity. Output nets are also de-mangled using `nextpnr_timing_analyzer::normalize_net_name`.
- **Carry Chain vs Fabric LUT Breakdown**: Dedicated FPGA carry primitives (`SB_CARRY`, `CCU2C`) propagate roughly an order of magnitude faster than routed fabric `SB_LUT4` hops. When paths traverse carry primitives, both the path headers and per-stage summaries break down total structural depth into fabric LUTs and carry hops (e.g. `Depth: 19 (8 LUTs + 11 carry)` and `(1 LUT + 3 carry)`), enabling accurate interpretation of structural depth vs physical delay.
- **Declared Module Resolution via `verilog_module_scanner`**: Previously, `verilog_logic_depth_tool` passed `args_.requested_module` directly to Yosys `-top` without consulting `verilog_module_scanner::discover_modules_in_files`, causing failures when a file stem (`alu` for `alu.sv` declaring `alu_mod`) or RTL instance name (`cpu8008` for `cpu`) was passed, or falling back to `cfg.top_module` even when `file` was explicitly provided. Calling `verilog_module_scanner::resolve_module_name` after gathering sources resolves declared module names from `file`, file stems, and RTL instances.
- **Project-Relative `file:line` & Configurable RTL Code Snippets (`show_code`)**: Converts source coordinates to project-relative paths and supports `show_code` (default `1`, aliases `code_lines`, `snippet_lines`, `include_code`, accepts integer or boolean) to display concise 1-line RTL statements inline on stages and endpoints by default, multi-line context when `show_code > 1`, or no snippets when `show_code = 0`/`false`.
