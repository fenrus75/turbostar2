# Nextpnr Timing Analyzer (`nextpnr_timing_analyzer`)

## Goals & Constraints

- **Purpose**: Parses nextpnr physical place-and-route timing and utilization reports (`timing.json`), correlates physical cell and interconnect net names against Yosys netlist JSON (`main.json`), and attributes delays back to original SystemVerilog `file:line` source anchors.
- **Reg -> Reg Exclusivity**: Focuses on synchronous register-to-register paths (`from posedge -> to posedge`) by default, excluding external pad-to-reg or reg-to-pad paths that do not reflect internal clock frequency bottlenecks.
- **Delay Decomposition**: Decomposes delay into logic delay (`logic`, `clk-to-q`) and routing delay (`routing`), showing their percentage contributions to reveal whether a bottleneck is caused by deep logic depth or interconnect wire congestion.
- **On-Demand Flow**: Integrates directly with Yosys and nextpnr (`nextpnr-ice40`, `nextpnr-generic`, `nextpnr-ecp5`) to run synthesis and place-and-route on demand when pre-generated reports are not supplied.

## Lessons Learned

- **Physical Cell Name Normalization**: nextpnr physical packing appends suffixes such as `_LC`, `_DFFLC`, `_RAM`, and `$sb_io`. Stripping these alongside trailing slice indices (`_2`) restores direct correspondence with netlist cells.
- **Netname Prefix Matching & RTL Source Prioritization**: Intermediate LUTs generated by Yosys carry names prefixed by the net/signal they drive. Prefix-matching against `netnames` in the netlist resolves RTL source line anchors even when cell-level `src` attributes point to internal Yosys techmap templates (`cells_map.v`). Furthermore, `resolve_cell_src` and hop formatting explicitly override library template locations (`is_library_source`) whenever a netname or alternative anchor provides user RTL coordinates, ensuring critical path reports direct the optimizer to actionable RTL rather than techmap fabric internals.
- **Yosys Command-Line Argument Formatting**: In on-demand synthesis, each source file must be passed as an individual CLI argument (`yosys -p <pass> <file1> <file2> ...`) rather than space-joined or wrapped into a single string argument, which caused Yosys to treat the space-joined files as a single non-existent filename with "Can't guess frontend (missing -f option)". Additionally, module names inside the `-p` pass (such as `-top <module>`) must not be enclosed in quotes because Yosys treats quotes literally as part of the module identifier.
- **Net Fanout & Physical Tile Distance Attribution**: Routing delays in FPGA timing reports are driven by net fanout (number of sinks) and physical placement distance across the die. The analyzer extracts chip grid coordinates `[x, y]` from each hop to compute Manhattan span distance (`|x1 - x2| + |y1 - y2|`), normalizes synthetic net names to their base RTL signal identifiers (`normalize_net_name`), and calculates exact net/bit sink counts from netlist cell input connections. Dominant routing bottlenecks are summarized per path with delay, clean net name, fanout, and tile span distance, giving the RTL designer immediate actionable hints for register duplication or pipelining without cluttering the report with raw die coordinates.
- **Carry Chain & Stage Collapsing with Name De-Mangling**: Multi-hop arithmetic carry ripples and cascaded LUTs produce verbose 10-20 step physical chains with noisy cell/net strings (e.g. `_SB_LUT4_O_I2_SB_...`). When `collapse=true` (the default), consecutive hops sharing the same techmap library location and base signal name or RTL location are collapsed into a single compact line showing summed logic/routing delays, total carry/LUT hops, aggregated bit ranges (`across carry[1..3]`), and maximum fanout/tile span. Techmap library template lines (e.g. `cells_map.v:26-27`) are stripped to `cells_map.v`, while real user RTL `file:line` locations are preserved. Uncollapsed per-hop detail remains available on demand via `collapse=false`.
- **Canonical Net Alias Selection & Register Inference**: When correlating physical cells and nets against flattened Yosys netlists, equivalent user nets sharing identical bit vectors are scored by driving cell source file match and hierarchy depth so higher-scope/driver names (`cpu8008.alu_out`) win over alphabetically-first sink port aliases (`cpu8008.A_reg.load_value`), and DFF endpoints resolve their true RTL register names via `yosys_netlist_reader::infer_register_from_src`.
- **Multi-Endpoint Top-K Extraction via `detailed_net_timings` & LUT+DFF Packing Correlation**: `nextpnr --report` only emits one path per clock domain in `"critical_paths"`. To surface `TopK > 1` distinct physical bottlenecks, `parse_timing_json` also parses `"detailed_net_timings"` (handling both scalar and `[min, max]` array `"delay"` formats across `nextpnr` versions). Because `nextpnr` packs 1-to-1 `LUT -> DFF` pairs into a single logic cell named after the LUT (`_LC`), `parse_netlist_json` maps 1-to-1 LUT outputs to their packed DFF cell (`lut_to_packed_dff_`) and maps DFF `Q` outputs to user registers (`dff_to_reg_name_`), while grouping sibling submodule instances sharing the same RTL declaration and driving net so that `TopK` reveals the true timing cliff across distinct subsystems.
- **Adaptive Multi-Seed Place-and-Route**: Because `nextpnr` placement has ~10–15% seed-to-seed Fmax variance on small designs, `synthesize_and_route` synthesizes the netlist once with Yosys and then executes `nextpnr` starting with `--seed 1`. When individual `nextpnr` runs are fast enough to stay within a 10-second wall-clock budget, it runs up to 5 seeds (`--seed 1..5`), selects the median-Fmax seed for the detailed critical path report, and displays the median Fmax alongside the `min–max` Fmax range across seeds.
- **Hop-by-Hop Segment Reporting (`show_segments=true` / `verbose=true`) & Stage Boundary Tracking**: When `show_segments=true` is enabled, `generate_timing_markdown` emits a `- **Segments (Hop-by-Hop)**:` breakdown for each critical path showing hop type (`[clk-to-q]`, `[routing]`, `[logic]`, `[setup]`), delay in `ns`, primitive cell type (`SB_DFFER`, `SB_LUT4`, `ICESTORM_LC`, etc.), input/output pins, tile coordinates, and demangled + raw intermediate net names. Stage merging tracks `has_routing` per stage so an outgoing routing hop merges into its driving cell's stage without chaining `last_cell = to_cell` into subsequent cells from different RTL locations when `collapse=false`.
- **Inline & Multi-Line RTL Source Snippets (`show_code`)**: `generate_timing_markdown` accepts `show_code` (default `1`), emitting a concise 1-line RTL statement inline (`| `<stmt>``) for each stage and start/end location when `show_code == 1`, a numbered multi-line `systemverilog` block when `show_code > 1`, or no code snippets when `show_code == 0`.
