# Verilog Simulate Tool (`verilog_simulate_tool`)

## Goals & Responsibilities
Compiles and executes a SystemVerilog/Verilog testbench together with the project's synthesizable RTL using Verilator (`--binary --timing --trace`), generates or updates the simulation waveform (`.vcd`), pre-warms `vcd_parser_cache`, and returns simulation output along with a VCD summary and concrete next-step `vcd_file_info` / `vcd_wave` commands.

Key capabilities:
1. **Zero-Config Testbench & RTL Discovery**: Automatically locates testbench files (`tb/`, `testbench/`, `tb_*.sv`, `*_tb.sv`), extracts the top-level testbench module name, and combines it with all synthesizable RTL under `sv_path`.
2. **Module-Targeted & Hierarchical Testing (`module`, `hierarchical`, `level`)**: Runs all testbenches associated with a target RTL module (via `verilog_configure_testbench` in `turbostar.json` or auto-discovered by instantiation). When `hierarchical: true`, traverses the submodule tree bottom-up (leaf submodules first, target module last) and filters testbenches by cumulative `level` (`quick` $\subset$ `comprehensive` $\subset$ `extreme`).
3. **Waveform `$dumpfile` Collision Detection & Renaming**: Detects ahead of time if multiple testbenches write to the same `$dumpfile("...")` VCD path. Only when a collision exists, renames the generated waveform for colliding testbenches to `<tb_stem>.vcd` (along with `<tb_stem>.previous.vcd` and `<tb_stem>.lastpass.vcd`) and warns the agent to give each testbench a unique `$dumpfile` filename.
4. **Automatic `$readmemh` / `$readmemb` Asset Staging**: Scans source files for relative `$readmemh`/`$readmemb` initialization filenames (e.g. `ram_init.hex`) and stages symlinks in the simulation working directory so memory initialization succeeds without manual Makefile wrapper steps.
5. **Automatic Waveform History (`<stem>.previous.vcd` & `<stem>.lastpass.vcd`)**: Before executing the simulation binary, preserves any existing `.vcd` waveform as `<stem>.previous.vcd`. When the simulation testsuite passes (`PASS` / `PASSED` / `successfully` without errors), also snapshots `<stem>.lastpass.vcd` so multi-iteration debugging sessions never lose their last known-good reference trace.
6. **LRU Cache Warming & Actionable Guidance**: Immediately parses the generated `.vcd` into `vcd_parser_cache` and emits copy-pasteable `vcd_file_info(...)`, `vcd_wave(...)`, and `vcd_compare(...)` tool calls tailored to the discovered hierarchy, signals, and pass/fail status.

## Lessons Learned
- **Two-Phase Parallel Compile + Serial Run Pipeline**: `verilator --binary` is a pure compilation step that accounts for ~85-90% of wall-clock latency when running multiple testbenches. Splitting `verilog_simulate` into Phase 1 (parallel `verilator --binary --build-jobs <N>` across `std::thread::hardware_concurrency()` workers, with per-testbench `--Mdir` disambiguated by `<tb_stem>_<top_mod>`) followed by Phase 2 (serial native binary execution and VCD post-processing) achieves full multi-core compilation speedup while avoiding race conditions on `project_root`, `$dumpfile` collision stashing, `$readmemh` symlink staging, and the 2-slot `vcd_parser_cache`.
- Running Verilator without `-flto` and placing `--Mdir` (resolved via `std::filesystem::absolute`) in the project temporary directory avoids polluting the repository with `obj_dir/` while keeping incremental C++ rebuilds fast.
- Passing `CCACHE_DISABLE=1 OBJCACHE=` to `verilator` prevents Verilator's generated Makefile from failing when `~/.cache/ccache` is mounted read-only inside the subprocess execution sandbox.
- Warming `vcd_parser_cache` at the end of `verilog_simulate` eliminates redundant VCD parsing on the immediately following `vcd_file_info` or `vcd_wave` call.
- Keeping both `<stem>.previous.vcd` and `<stem>.lastpass.vcd` prevents multi-step debugging loops from overwriting the last known-good waveform when two or more consecutive edits fail.
- Running `vcd_compare_tool::quick_compare` automatically at the end of `verilog_simulate` (before overwriting `<stem>.lastpass.vcd` on a passing run) reports immediately when the new waveform is **IDENTICAL** to `<stem>.previous.vcd`, and when `<stem>.previous.vcd` differs from the prior `<stem>.lastpass.vcd` (e.g. after one or more failed runs), compares against **both** `.previous.vcd` and prior `.lastpass.vcd` so the agent sees both whether its fix altered the failed trace and whether it restored cycle-identical behavior to the last passing baseline.
- **3-State Verdict (`PASS`, `INFO (no assertions)`, `FAIL`)**: Probe/trace testbenches (e.g. `tb_stack_probe.sv` and `tb_stackprobe.sv`) often log internal signals via `$display`/`$monitor` and call `$finish` cleanly without printing a `PASS`/`FAIL` assertion summary or calling `$dumpfile`. Classifying these as `INFO (no assertions)` rather than `FAIL`—and having `extract_dumpfile_path` return `""` when neither `$dumpfile` nor `$dumpvars` is present—prevents clean probe runs from failing module-level test suites or triggering false `$dumpfile` collision warnings.
- **Directive Collision Remediation & Submodule Hierarchy Guidance**: When a `$dumpfile` collision is detected, `verilog_simulate` and `verilog_configure_testbench` emit a concrete `Recommended Fix` showing the exact `$dumpfile("dump_<stem>.vcd")` rename for each colliding testbench. Similarly, when `verilog_simulate(module="...", hierarchical=false)` finds no direct testbench for a parent module whose submodules *do* have testbenches, it reports the discovered submodule testbenches and recommends either a one-time `verilog_configure_testbench(module="...", hierarchical=true)` project setting or a one-off `verilog_simulate(module="...", hierarchical=true)` call. When a module is configured in `"hierarchical_modules"`, `verilog_simulate(module="...")` runs with `hierarchical=true` by default and explicitly reports `- **Hierarchy Mode**: Ran with hierarchical=true due to project settings for ... in turbostar.json (pass hierarchical=false to override)`.
- **Compact Hierarchical Regression Output & Fast Watchdog**: When running $>2$ testbenches (or when `summary_only: true` / `quiet: true` is passed), `verilog_simulate` omits detailed per-testbench stdout/compile sections for clean passing testbenches by default—showing the summary table plus detailed sections only for failed, diverged, colliding, or probe-only testbenches (pass `verbose: true` to force all sections). Additionally, the default per-testbench timeout is 10 seconds (`timeout_sec`, or sub-second `timeout_ms`) so hung testbenches fail fast without hitting the outer MCP timeout.
