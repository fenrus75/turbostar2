# Performance Manager (`perf_manager`)

## Goals and Constraints
- **Zero-Dependency CPU Cycle Profiling**: Collects and resolves flat CPU hardware cycle samples (`PERF_COUNT_HW_CPU_CYCLES`) generated by `libturbocatch.so` (`src/crash_catcher/perf_catcher.c`) via `perf_event_open(2)`.
- **Batch Symbol Resolution**: Aggregates instruction pointer (IP) histograms from `perf_samples_<pid>.dat` and resolves unique IPs against `/proc/<pid>/maps` (`perf_maps_<pid>.txt`) using `address_lookup::resolve_addresses`.
- **Multi-Run Profile Storage**: Maintains both the active profile and per-`run_id` profiles for editor heatmap visualization and agent tools (`agent_get_profile_summary`, `agent_get_profile_details`).
- **Dynamic Line Tracking**: Implements `document_listener` to shift or invalidate per-line profile percentages when source files are edited.

## Lessons Learned
- **`_Exit` / `_exit` Interception in `libturbocatch.so`**: Executables such as `agentcli_replay` call `std::_Exit(0)` to bypass global C++ static destructor ordering issues. Because `_Exit` skips `__attribute__((destructor))` functions, `perf_catcher.c` must also intercept `_exit` and `_Exit` to flush `turboperf_shutdown()` before invoking `SYS_exit_group`.
- **Filtering Wrapper Shells & Child Processes**: When `command_runner` launches a binary under `bash -c`, both the wrapper shell and any child processes (`popen`, `clangd`) inherit `LD_PRELOAD` and `TURBOSTAR_PERF_DIR`. Skipping shell wrappers (`bash`, `sh`, `dash`) in `turboperf_init` and calling `unsetenv("TURBOSTAR_PERF_DIR")` once the target binary initializes prevents child processes from generating competing sample files. When multiple sample files do exist, `parse_and_resolve` selects the largest sample file and cleans up all raw artifacts in `perf_dir`.
