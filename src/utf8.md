# UTF-8 and String Formatting Utilities (`utf8`)

## Goals
The `utf8` namespace (`src/utf8.h`, `src/utf8.cpp`) provides foundational string inspection, sanitization, terminal display-width measurement, line wrapping, and identifier case-conversion utilities used across the editor UI and LLM agent subsystems.

## Architecture and Constraints
- **UTF-8 Sequence Handling**:
  - Computes character counts (`length`), terminal column widths (`display_width`), and byte/character offset translations (`char_to_byte_offset`, `byte_to_char_pos`) without throwing exceptions on malformed byte sequences.
  - Provides unified, symmetric ASCII and Unicode whitespace detection (`is_space_at_byte`, `is_space_at_char`) recognizing ASCII whitespace (`std::isspace`) as well as Unicode space separators (U+00A0 NBSP, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000 CJK fullwidth space), maintaining exact semantic symmetry between byte- and character-addressed checks.
  - Provides Unicode- and ASCII-aware whitespace trimming utilities (`trim_leading_whitespace`, `trim_trailing_whitespace`, `trim_full`, `trim`) that operate on `std::string_view` and return new strings without modifying the input in place.
  - Provides zero-allocation whitespace checking (`is_whitespace_only`) that scans by character boundaries and verifies whether a string consists entirely of whitespace or is empty.
  - Provides unified alphanumeric detection (`is_alnum`, `is_alnum_at_byte`, `is_alnum_at_char`, `is_alnum_only`, `is_not_alnum_only`) with optional `std::string_view extra = {}` allowlist. Eliminates `<cctype>` signed-char undefined behavior, enforces strict ASCII `[0-9a-zA-Z]` core matching independent of locale, and properly supports multi-byte Unicode characters in `extra` on codepoint boundaries. `is_not_alnum_only` provides a clean validator idiom that safely accepts empty strings while flagging any disallowed characters without double negation.
  - Provides `is_valid_utf8` and `sanitize` to defend UI rendering and JSON serialization against invalid UTF-8 sequences or embedded NUL bytes.
- **Terminal Output Sanitization**:
  - `sanitize_terminal_output` strips ANSI CSI/OSC escape sequences (including incomplete trailing sequences) so terminal dumps remain safe for TUI and LLM consumption.
- **ASCII and String Case Transformations (`to_lower`, `to_upper`)**:
  - Provides `constexpr` single-character (`to_lower(char)`, `to_upper(char)`) and single-allocation `std::string_view`-based string conversions (`to_lower(std::string_view)`, `to_upper(std::string_view)`).
  - Operates purely on ASCII byte ranges (`'A' <= c && c <= 'Z'`, `'a' <= c && c <= 'z'`) without relying on the C locale or `<cctype>` functions, eliminating signed char undefined behavior and guaranteeing multibyte UTF-8 codepoints and high bytes ($\ge 0x80$) remain intact.
- **Identifier Case Conversion (`to_snake_case`, `to_PascalCase`, `to_camelCase`)**:
  - Converts identifier strings across the three primary naming conventions: Linux kernel style (`snake_case`), Google/Antigravity style (`PascalCase`), and Microsoft/Copilot style (`camelCase`).
  - Handles multi-letter uppercase acronyms (e.g., `HTMLParser` -> `html_parser`, `URL` -> `url`) and digit-to-uppercase transitions (`utf8Char` -> `utf8_char`).

## Lessons Learned
- **Whole-Character Deletion in Trimming**: Trimming multibyte Unicode whitespace characters (such as U+00A0 NBSP or U+3000 CJK fullwidth space) cannot simply decrement byte counts. Trailing trimming must step backwards over UTF-8 continuation bytes (`(c & 0xC0) == 0x80`) to find the character lead byte, check `prev + char_len == end && is_space_at_byte(s, prev)`, and delete the whole multi-byte sequence to prevent slicing valid characters in half or corrupting preceding text.
- **Multi-Byte Allowlist Matching and Continuation Byte Safety**: When extending alphanumeric checks with custom character allowlists (`extra`), byte-by-byte matching on non-ASCII characters risks false-positive matching against UTF-8 continuation bytes (`0x80..0xBF`) or shared lead bytes. When `byte >= 0x80`, multi-byte matching must extract the entire codepoint glyph (`s.substr(offset, clen)`) and compare it against `extra`, rejecting continuation bytes and truncated sequences.
- **Incomplete Escape Sequence Stripping**: When truncating raw PTY streams, an ANSI escape sequence may be cut off mid-sequence at the end of the buffer. Stripping trailing partial escape sequences prevents leaking raw control prefixes into the UI.
- **Cross-Harness Identifier Normalization**: Different LLM harnesses train models on distinct parameter casing conventions (`start_line`, `StartLine`, `startLine`). Providing deterministic, round-trip case conversion helpers allows the tool validator and MCP server to bridge these conventions seamlessly.
- **Case Conversion Roundtrip Invariants & UTF-8 Boundaries**: In `to_snake_case`, checking `(prev >= 0x80)` ensures that multibyte UTF-8 characters followed by uppercase ASCII words (such as `CaféAuLait` -> `café_au_lait`) preserve word delimiters. In `to_PascalCase`, preserving word-boundary underscores when the subsequent character is non-capitalizable (e.g. `x86_64` -> `X86_64`, `step_1` -> `Step_1`, or emoji/CJK scripts) maintains idempotency under combinatorial case transformations.
- **ASCII Case Folding and UTF-8 Byte Preservation**: Using `<cctype>` `std::tolower` or `::tolower` on raw `char` can lead to undefined behavior when `char` is signed and passed a value $< 0$ (e.g. UTF-8 multi-byte lead or continuation bytes). Pure ASCII branch checks (`uc >= 'A' && uc <= 'Z'`) completely avoid `<cctype>` locale dependencies, prevent sign-extension UB, and leave multibyte UTF-8 characters and binary data unmodified.
- **Inverted Delimiter Logic for Multilingual Code Words**: Enumerating all legal Unicode letters and ideographs for C/C++ identifiers requires over 130,000 codepoints. Instead, inverting the problem by filtering out fixed delimiters (ASCII operators/punctuation, Unicode spaces, typographic quotes/dashes, CJK punctuation) provides $O(1)$ token extraction across French accents, German umlauts, Greek mathematical symbols, and CJK variable names.
- **Fullwidth Punctuation UTF-8 Byte Boundaries**: In Unicode, fullwidth ASCII variants (U+FF01..U+FF5E) span two distinct UTF-8 lead bytes: `\xEF\xBC` (U+FF01..U+FF3F) and `\xEF\xBD` (U+FF40..U+FF5E). Fullwidth brackets `［＼］＾` are located at `\xEF\xBC\xBB..\xEF\xBC\xBE`, while fullwidth low line `＿` (U+FF3F) is at `\xEF\xBC\xBF` and must be preserved as an identifier character, followed by backtick `｀` at `\xEF\xBD\x80` and braces/tilde `｛｜｝～` at `\xEF\xBD\x9B..\xEF\xBD\x9E`. Thorough branch coverage testing is essential for verifying exact multi-byte boundary conditions.
- **Delimiters, Whitespace, and Identifier Partitioning**: A character in source text is cleanly partitioned into whitespace (`is_space_at_byte`), word/identifier glyph (`is_word_char_at_byte`), or punctuation/delimiter (`is_delimiter_at_byte`). Evaluating `is_delimiter_at_byte` by verifying that the byte is not whitespace, not an identifier token, not a continuation/truncated byte, and not an unprintable control byte guarantees consistent token boundaries across ASCII and Unicode scripts.
