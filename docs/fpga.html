Hardware, RTL & FPGA Engineering

The Missing Glue Between AI Agents & Hardware Design

Software agents thrive on text diffs and stack traces, but digital hardware lives in clock edges, combinational LUT cones, and gigabyte waveform dumps. Turbostar's verilog tool family bridges the divide—giving LLM agents natural, deterministic primitives for SystemVerilog linting, tiered simulation, cycle-accurate VCD inspection, LUT area & logic depth analysis, and physical place-and-route timing closure.

Why Hardware Agents Need Purpose-Built Glue

With raw shell commands, RTL design is hostile to AI agents. With the right primitives, the workflow becomes effortless.

Ask an unassisted coding agent to build or debug an CPU core in SystemVerilog using only bash and grep: a single simulation emits a 500 MB .vcd dump that overflows the context window, running Verilator on a multi-testbench directory fails with duplicate top modules, and "optimizing" a critical path blindly unrolls multiplexers until LUT area explodes and physical routing fails timing.

Turbostar acts as the domain-aware translation layer between open-source EDA toolchains (Verilator, Yosys, Icarus Verilog, and nextpnr) and the agent. Every tool accepts high-level intent—module names, clock-cycle windows, enum state symbols, and target frequencies—and returns compact, line-attributed engineering reports. Tested end-to-end by autonomous agents designing complete 8008/8080-class CPU cores from scratch, the tools feel completely natural to the model at every step of the RTL lifecycle.

Dual-Engine Lint & Synthesis Triage

Catch hardware bugs before a single clock cycle is simulated. verilog_compile combines ultra-fast Verilator static linting with Yosys RTL synthesis checks in a single call.

  • Automatic Hierarchy Isolation: Pass module="alu" and Turbostar automatically scans your RTL tree, resolves transitive package and submodule dependencies, and excludes unrelated testbenches—preventing duplicate symbol errors.
  • Hardware Hazard Categorization: Raw compiler logs are distilled into prioritized sections highlighting Combinational Loops, Inferred Latches, Multi-Driven Nets, and Width Mismatches with exact file.sv:line locations.
  • SystemVerilog Package Ordering: Automatically orders package definitions and header includes ahead of dependent RTL modules without manual filelists.
# Tool call: verilog_compile(module="cpu_8080_core")
=== Compilation & Synthesis Triage: cpu_8080_core ===
Status: WARNING (0 errors, 2 synthesis hazards)
Scoped Sources: pkg_types.sv, alu.sv, regfile.sv, cpu_8080_core.sv

[Inferred Latches]
  rtl/cpu_8080_core.sv:142: Warning: Latch inferred for signal
  'next_mem_wdata[7:0]' in always_comb block (missing default assignment
  when state == STATE_HALT).

[Width Mismatches]
  rtl/alu.sv:68: Warning-WIDTH: Operator ADD expects 9 bits on
  RHS, but 'carry_in' provides 1 bit.

Tiered Simulation & Auto-Diffing Waveforms

Hardware verification requires fast inner loops during active debugging and exhaustive sweeps before sign-off. verilog_simulate and verilog_configure_testbench manage testbench execution and waveform history automatically.

  • Quick, Comprehensive & Extreme Tiers: Classify testbenches by execution tier so the agent runs sub-second smoke tests after every edit and full instruction-set regressions before committing.
  • Zero-Friction Hex & ROM Staging: Automatically stages $readmemh and $readmemb firmware images into the simulation sandbox so relative paths always resolve cleanly.
  • Automatic Waveform Snapshots & Diffs: Passing runs snapshot .lastpass.vcd while every run preserves .previous.vcd. When a change breaks a testbench, verilog_simulate automatically diffs the new trace against the last passing waveform and reports the exact first diverging clock cycle and signal.
# Tool call: verilog_simulate(tier="quick")
=== Simulation Summary (Tier: quick) ===
[PASS] tb_alu            (0.18s) - 256 vectors verified
[FAIL] tb_cpu_8080_core  (0.42s) - Assertion failed at t=145000ps

[Automatic Waveform Regression vs. tb_cpu_8080_core.lastpass.vcd]
First divergence at t = 115000 ps (posedge clk #11):
  dut.state        : STATE_EXEC_ALU (expected: STATE_WRITEBACK)
  dut.reg_a[7:0]   : 8'h3C          (expected: 8'h3D)
  dut.alu_cin      : 1'b0           (expected: 1'b1)

Cycle-Accurate VCD Waveform Intelligence

Instead of dumping raw VCD text into the prompt, Turbostar's 7-tool VCD suite gives the agent an interactive logic analyzer tailored for LLM reasoning.

  • Live SystemVerilog Enum Discovery: Automatically parses typedef enum declarations across your RTL and headers—rendering state machines as FETCH (0) or DECODE (1) instead of raw hex, and automatically revalidating labels whenever enum states are added or reordered in source code.
  • Strobe & Enable Qualification: Pair buses with valid strobes via vcd_signal_qualifier so inactive cycles render as -, keeping the agent focused on valid bus transactions.
  • Temporal Search & Idle Collapsing: Query multi-signal conditions (`state == 3 && ready == 1`), collapse hundreds of idle clock cycles into a single summary line, and trace any waveform net straight back to its drivers and loads in RTL with vcd_signal_to_code.
# Tool call: vcd_wave(signals=["clk","state","pc","abus","dbus"], ...)

Logic Depth, LUT Area & Timing Contracts

Agents optimizing purely for clock frequency often duplicate logic cones until FPGA resource utilization explodes. verilog_logic_depth and verilog_update_timing give the agent simultaneous visibility into combinational depth and resource area in seconds.

  • Bottleneck Sink Grouping: Critical paths are grouped by destination sink with compacted bit-bus ranges (`pc[0..15]`) and step-by-step LUT/MUX/CARRY hop traces mapped directly to file.sv:line.
  • Module Area Summary: Every report includes a synthesized cell breakdown (LUTs, Flip-Flops, Carry cells, BRAMs, and DSPs) so the agent balances speed against LUT budget.
  • Persistent .timing.md Sidecars: verilog_update_timing (and the standalone turbostar-verilog-update-timing CLI) generates per-module Markdown timing contracts across the entire repository in parallel.

Physical Place-and-Route Timing Closure

Pre-synthesis logic depth is only half the story—on real FPGAs, long Manhattan wire routes and high-fanout control nets often dominate the critical path. verilog_pnr_timing runs full Yosys synthesis + nextpnr physical placement and routing on demand.

  • Achieved Fmax vs. Target Constraint: Evaluates real post-routing setup slack against your target clock constraint in turbostar.json (configurable via verilog_project_settings).
  • Logic vs. Routing Delay Split: Decomposes every critical path hop into cell propagation delay vs. physical interconnect wire delay.
  • Physical Tile Distance & Fanout: Reports net fanout and physical chip tile delta (dx, dy) alongside exact SystemVerilog source lines, empowering the agent to pipeline long routes or replicate high-fanout registers.
# Tool call: verilog_pnr_timing(module="cpu_8080_core")

12 Specialized Tools Across the RTL Lifecycle

Activate the verilog tool family in Turbostar or expose it to any external agent CLI via turbomcp.

🛠️

Lint, Synthesis & Config

Fast static verification and persistent FPGA target configuration without manual Makefiles.

  • verilog_compile: Dual Verilator lint + Yosys synthesis triage with submodule scoping.
  • verilog_project_settings: Configure target FPGA family (ice40, ecp5, gowin, xilinx), part, package, and target clock MHz.
⚡

Tiered RTL Simulation

Automated testbench discovery, tiered execution, and regression waveform snapshots.

  • verilog_simulate: Run Icarus Verilog or Verilator testbenches with auto-diffing against .lastpass.vcd.
  • verilog_configure_testbench: Assign testbenches to quick, comprehensive, or extreme tiers and register ROM/hex data files.
📈

Waveform Inspection

Token-efficient, clock-aligned VCD tables and temporal condition search.

  • vcd_file_info: Inspect hierarchy scopes, timescale, time bounds, and clock candidates.
  • vcd_wave: Clock-aligned ASCII/Markdown tables with idle-cycle collapsing and bus formatting.
  • vcd_search: Find timestamps matching complex multi-signal boolean expressions or edges.
🏷️

Semantic Trace & Diffing

Bridge raw signal bits back to high-level SystemVerilog types and source lines.

  • vcd_signal_labels: Auto-discover typedef enum state names with live RTL change detection.
  • vcd_signal_qualifier: Mask bus values during inactive valid/enable cycles.
  • vcd_compare: Cycle-by-cycle diff between two VCD traces with clock-edge alignment.
  • vcd_signal_to_code: Trace VCD nets to RTL declarations, drivers, and loads.
⏱️

Logic Depth & Area

Instant combinational LUT cone analysis and module resource tracking.

  • verilog_logic_depth: Per-module critical path hop traces, sink grouping, and LUT/FF/Carry/BRAM area summaries.
  • verilog_update_timing: Parallel batch updater for <module>.timing.md sidecars across the project.
📐

Physical Place & Route

Post-routing timing closure with physical chip coordinates and routing delay breakdowns.

  • verilog_pnr_timing: Full Yosys + nextpnr physical timing analysis reporting Fmax, slack, logic vs. wire delay, fanout, and (dx, dy) tile distance.
  • turbostar-verilog-update-timing: Standalone CLI binary for CI pipelines and git hooks.

Open-Source FPGA Toolchain Setup

Turbostar integrates directly with standard open-source SystemVerilog and FPGA synthesis packages.

1. Install EDA Dependencies & Project Template

Install the open-source verification and synthesis tools from your distribution package manager or OSS CAD Suite. Turbostar also ships with a ready-to-use systemverilog project template containing a pre-configured turbostar.json and an agent workflow guide (AGENT.md).

  • Lint & Simulation: verilator and iverilog (Icarus Verilog + vvp).
  • Synthesis & Logic Depth: yosys (supports generic gate synthesis plus ice40, ecp5, gowin, and xilinx targets).
  • Physical Place & Route: nextpnr-ice40, nextpnr-ecp5, or nextpnr-gowin alongside fpga-icestorm / prjtrellis.
# 1. Install open-source RTL & FPGA tools (Debian/Ubuntu)
sudo apt install yosys verilator iverilog \
  nextpnr-ice40 fpga-icestorm

# 2. Activate in an agent session or via MCP
# Call activate_tool_family(family="verilog")
# or launch turbomcp with --all-tool-families
turbomcp --project-dir /path/to/rtl-project

# 3. Or run standalone batch timing & area analysis
turbostar-verilog-update-timing --target ice40
