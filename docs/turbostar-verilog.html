Standalone Command-Line Toolkit

Getting Started with turbostar-verilog

turbostar-verilog packages Turbostar's entire SystemVerilog, FPGA synthesis, timing analysis, and VCD waveform engine into a single command-line binary. Use it interactively in your terminal, wire it into Makefiles and CI pipelines, or use it to bootstrap turbostar.json before launching an AI hardware agent. All examples below use real data from the 11-module Intel 8008 CPU design in examples/test8008.

Step 1 • Project Setup

Configure Target FPGA Architecture in turbostar.json

Every synthesis, timing, and simulation command reads project defaults from turbostar.json in your project root. Instead of hand-editing JSON or maintaining sprawling synthesis Makefiles, run turbostar-verilog config to set your target FPGA family, part, package, top-level module, clock constraint (in MHz), pin constraints (.pcf), and RTL source directory. Running turbostar-verilog config with no flags inspects the current configuration and verifies your installed EDA binaries.

  • Supported Targets: ice40 (Lattice iCE40 with -abc9 LUT4/carry mapping), ecp5 (Lattice ECP5), gowin, xilinx, or generic.
  • Zero-Flag Inspection: Run turbostar-verilog config at any time to inspect active settings, detected yosys/nextpnr binaries, and discovered .pcf files.
$ cd examples/test8008
$ turbostar-verilog config --target ice40 --device hx8k --package cb132 \
    --top main --freq 80 --pcf pcf/cu.pcf --sv-path sv
Successfully saved FPGA project configuration to `/home/user/test8008/turbostar.json`.

Step 2 • Verification Mapping

Auto-Scan Testbenches & Bind Verification Tiers (config --scan)

In multi-module designs, running every system testbench after a one-line ALU edit wastes minutes, while running only a leaf testbench misses integration bugs. On an existing project, turbostar-verilog config --scan inspects every testbench in your workspace, identifies the Device Under Test (preferring explicit dut/uut instances over helper RAM/bus models), marks composite parent modules with hierarchical=true, and writes the complete mapping to turbostar.json in one step—warning immediately if two testbenches collide on the same $dumpfile VCD path.

  • One-Command Auto-Discovery (-s, --scan): Populates turbostar.json for all workspace testbenches (9 testbenches in examples/test8008, or all 38 testbenches in examples/test8080) and enables bottom-up hierarchical verification on composite parent modules (cpu, main, top).
  • Cumulative Test Tiers (--tb ... --level): Fine-tune individual testbenches as quick (fast unit tests), comprehensive (subsystem integration tests), or extreme (long soak tests).

Step 3 • Static Verification & Synthesis

Fast Verilator Lint & Yosys Synthesis Triage (compile)

Raw synthesis logs bury critical multi-driver nets and latch inferences inside thousands of lines of LUT mapping progress. turbostar-verilog compile runs Verilator static analysis and Yosys synthesis while separating real hardware bugs (undriven nets, width mismatches, inferred latches) from routine style notes (unused wires).

  • Sub-Second Static Lint (-l, --lint-only): Checks syntax, port widths, and undriven signals across the module hierarchy in ~0.2 seconds.
  • Submodule Synthesis Scoping (-m <module> -s): Synthesize a single module or file in isolation without waiting for full-chip place-and-route.
$ turbostar-verilog compile --lint-only

Step 4 • Automated Simulation & Regression Diffing

Module-Targeted & Bottom-Up Hierarchical Simulation (sim)

turbostar-verilog sim compiles and runs your SystemVerilog testbenches with Verilator (`--timing --trace`), automatically stages any $readmemh/$readmemb initialization files, and compares every generated .vcd dump cycle-by-cycle against the prior run (.previous.vcd) and last passing baseline (.lastpass.vcd).

  • Single-Module Inner Loop (sim -m alu_mod): Runs only the testbenches associated with alu_mod and verifies whether the resulting waveform is identical to the previous run.
  • Bottom-Up Hierarchical Verification (sim -m cpu or -H): Computes the transitive dependency graph of cpu, executes leaf unit testbenches first (`register` → `regsel` → `alu_mod` → `stack_mod` → `sequencer_mod`), and finishes with the top-level `cpu` integration testbench.

Step 5 • Structural Logic Depth & In-Place Port Annotations

Combinational LUT Depth, Area & In-Place // [timing: ...] Annotations

Timing analysis is the default mode of turbostar-verilog (also accessible via turbostar-verilog timing). It synthesizes the target module into technology-mapped LUTs and carry chains (using synth_ice40 -abc9 when configured for iCE40) and extracts input-to-register, register-to-output, and internal register-to-register logic levels alongside a cell area breakdown.

  • Single-Module Depth & Inline RTL (-m <module> -k <top_k>): Groups critical paths by bottleneck sink and prints the exact SystemVerilog statement at each hop alongside LUT and carry-chain counts.
  • Project-Wide Dry-Run Summary (--dry-run): Synthesizes every module in your project and prints a single comparison table of Reg->Reg Depth, LUTs, and FFs.
  • In-Place Port Annotations (-u, --update): Writes and updates vertically aligned // [timing: ...] comments directly on module port declarations inside your .sv files.

Step 6 • Post-Routing Physical Timing

Multi-Seed Place-and-Route Timing Closure (--pnr)

Pass --pnr to run full Yosys synthesis plus nextpnr physical placement and routing. When targeting the project's top module, turbostar-verilog --pnr applies your .pcf pin constraints; when given -m <submodule>, it runs unconstrained out-of-context submodule PnR and automatically evaluates multiple placement seeds to report median and min-max achieved Fmax.

  • Logic vs. Wire Routing Breakdown: Every critical path hop displays its exact logic delay, physical routing delay, net fanout (sink count), and chip Manhattan tile span.
  • Detailed Cell Segments (--segments): Pass --segments to expand any critical path into individual SB_LUT4, SB_CARRY, and routing interconnect hops.
$ turbostar-verilog --pnr -m alu_mod -k 2
> [!NOTE] Out-of-Context Submodule PnR (`alu_mod`): Analyzed submodule `alu_mod` with unconstrained I/O placement (configured project `top_module` is `main`).

Step 7 • Waveform Debugging from the Terminal

Cycle-Accurate VCD Inspection, Condition Search & RTL Net Tracing (vcd-*)

Instead of opening a GUI waveform viewer and manually adding signals after every simulation run, turbostar-verilog provides seven vcd-* subcommands that render clock-aligned waveform tables, toggle statistics, condition searches, cycle-by-cycle VCD diffs, and structural RTL net traces directly in your terminal.

  • Zero-Config Enum Auto-Discovery: vcd-info, vcd-wave, and vcd-search automatically scan your SystemVerilog typedef enum declarations so FSM states render as 0x1 (FETCH), 0x2 (DECODE), and 0x4 (RETIRE) without manual setup.
  • Module Boundary & Shorthand Signal Sampling: Pass an instance or module name like -i alu (or vcd-wave alu) to automatically sample all of its input and output ports, or pass leaf names like -s sequencer.state,current_ip,alu_out; vcd-wave resolves full hierarchical paths automatically and collapses identical idle clock cycles.
  • Structural Net Traceability (vcd-trace): Map any VCD signal back to every module port, wire declaration, driving cell, and sink load across your RTL hierarchy.

Step 8 • Regression Triage (vcd-compare)

Pinpoint First Cycle of Waveform Divergence Across 255 Signals

When an RTL edit or ROM change causes a testbench to diverge, hundreds of downstream registers drift on subsequent clock cycles. Every run of turbostar-verilog sim automatically preserves the prior waveform as .previous.vcd and the last passing waveform as .lastpass.vcd. Running turbostar-verilog vcd-compare diffs the two traces cycle-by-cycle on the reference clock edge and isolates the exact first clock tick and root-cause signals where behavior diverged—filtering out the downstream cascade.

  • Automatic Baseline Diffing in sim: Removing the FF (HLT) byte from ram_init.hex in examples/test8008 immediately triggers a divergence alert in sim at Tick 12.
  • Root-Cause Isolation at Tick 12: Out of 255 signals and 190 differing cycles, vcd-compare shows that Ticks 0–11 matched in lock-step and isolates the 9 memory-read and decode bus signals at Tick 12 where 0xFF became 0x44, complete with a copy-pasteable vcd-wave follow-up command.
# Remove the 'FF' (HLT) byte from ram_init.hex (06 41 36 80 F8 FF 44 -> 06 41 36 80 F8 44) and re-simulate:
$ turbostar-verilog sim --tb tb/tb_main.sv
#### Generated VCD Summary (`dump.vcd`)
- Detected Clock: `tb_main.clk` (202 posedge cycles, period: 10000 1ps)
- Total Signals: 255 across 18 hierarchy scope(s)
- Comparison vs. Previous (`dump.previous.vcd`): DIVERGED (102 signal(s) differ across 190 of 202 cycle(s); first difference at tick 12)

# Compare the candidate waveform against the previous baseline to isolate the root cause at Tick 12:
$ turbostar-verilog vcd-compare dump.previous.vcd dump.vcd
