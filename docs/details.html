1. Architecture Overview

Core design principles and subsystem sitemap of Turbostar.

Core Subsystems

Turbostar is built as a highly modular C++23 application. The core editor runtime decouples UI rendering from file management, language server communications, and AI tool orchestration.

  • Editor Core: Event queue dispatching, window tiling, document buffer management, and keybinding translation.
  • Agent Framework: Tool registration, security validation, subagent lifecycle management, and protocol transport wrappers.
  • Subprocess & Sandbox Layer: Process runner, PTY master allocation, systemd namespace isolation, and hardware signal handlers.

2. TUI Rendering & Buffer Management

Low-latency terminal graphics, double-buffered window frames, and keybinding translation.

Rendering Pipeline

The user interface uses a custom ncurses abstraction layer with optimized cell diffing to minimize terminal redraw latency even over remote SSH connections.

  • Double-Buffered Grids: Computes frame diffs in memory before emitting terminal escape sequences.
  • Coordinate-Free Windows: Tiled window borders are computed dynamically, supporting intuitive mouse drag-and-resize events.
tui --rendering-pipeline
# Render Pipeline Technical Details:
- Primary Frame Buffer: Off-screen character matrix
- Diff Engine: Cell-level comparison (char + color pair)
- Palette: Turbo Pascal 7 dark mode color map
- Input Translation: WordStar prefix key state machine

3. Performance Profiling & Hardware Counters

In-process cycle sampling, symbol resolution, and multi-run report storage.

Profiling Subsystem

Performance profiling operates via Linux perf_event_open syscalls injected through libturbocatch.so. Cycle counts are mapped back to source file lines using asynchronous DWARF symbol resolution.

  • Zero-Kernel Dependency: Direct hardware counter access without requiring external perf tools or kernel modules.
  • Multi-Run Storage: Reports are indexed in-memory by execution run_id, allowing agents to compare performance across optimization passes.
perf --subsystem-spec
# Perf Profiling Technical Specs:
- Hardware Event: PERF_COUNT_HW_CPU_CYCLES
- Interceptor: libturbocatch.so (LD_PRELOAD)
- Map Pairing: /proc/self/maps PID pairing
- Symbol Lookup: eu-addr2line / DWARF line tables
- Storage Key: run_id ("run_1", "run_2", "editor")

4. Sandboxing & Process Isolation

Security model, systemd namespace isolation, and pre-execution script validation.

Security Engine

All untrusted tool executions and child application processes run inside restricted Linux mount and PID namespaces created via systemd isolation.

  • Filesystem Security: Restricts read/write access to explicitly authorized project paths.
  • Static Analysis Checks: Automated Bandit scanning blocks insecure Python scripts prior to native execution.
sandbox --security-spec
# Sandboxing Architecture Specs:
- Namespace Boundaries: Mount, PID, IPC, Network (optional)
- Root FS Mount: Read-only tmpfs
- Project Mount: Read/Write bind-mount (restricted)
- Static Scanner: Bandit (Python AST inspector)

5. Virtual Context Paging Engine

Tiered context compression, memory-mapped history, and disk page-in upgrades.

Paging Architecture

To prevent context window overflow during extended agent interactions, Turbostar implements a memory-mapped context paging engine inspired by operating system virtual memory.

  • Tiered Compression: Converts full tool outputs and reasoning blocks into compact redirection markers.
  • On-Disk Persistence: Retains complete uncompressed conversation trajectories on disk for page-in retrieval.
paging --engine-spec
# Context Paging Technical Specs:
- Level 0: Full Content (Active Window)
- Level 1: Think-Removed Content (Compressed Reasoning)
- Level 2: Tool-Call Reduced Content (Redirection Tokens)
- Persistence Store: JSONL log trajectory store
